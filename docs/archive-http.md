# Native archive requests in 3.14.4

The reference APK is the unrelated Flutter application `com.readerapps.ao3_reader`,
version 1.6.5, from `apk/base.apk` (SHA-256
`a1b2f203c1f5b6a085eddc06428d7da597df948cb8c9399cc7e1b7ce9f91de9c`).
The local analysis recovered Dart AOT handlers and the Java Android plugin.

The APK contains several request paths: Dart HTTP, a headless WebView, and an
Android OkHttp plugin. Remote configuration can select a path and override its
headers. APK inspection establishes the compiled defaults, not the configuration
that was active on a particular phone.

This release implements the Android OkHttp path in the legacy app. The persistent
client supports HTTP/2 and uses the reference plugin's 20-second connect/read
timeouts and default TLS configuration. The APK also offers optional cipher-list
variants; those are not enabled here because the compiled default is zero.

Requests use the recovered Chrome 120 Android user agent, HTML Accept value,
`en-US,en;q=0.9`, `Upgrade-Insecure-Requests: 1`, and `gzip, deflate, br`.
All three compression formats are decoded before parsing. Host/authority comes
from the destination rather than a hard-coded host. The sign-in WebView uses the
same user agent and cookie jar. Response cookies, including redirect cookies,
are saved before the next request.

There are deliberate constraints around that behaviour:

- Every redirect must remain HTTPS on an archive host, without credentials or a
  custom port. Redirects are bounded and cookies are looked up for each URL.
- A POST is submitted once. The existing form handler can inspect its response
  and fetch the confirmation page without replaying the write.
- The old three-attempt native 5xx retry loop is removed. Queue retries retain
  their existing pacing. OkHttp retains its default connection recovery for
  reads; recovery is disabled for writes so a form is not replayed.
- Server `Retry-After` reaches the shared queue cooldown, including when a single
  work receives a 429. A 525 is reported as the secure origin connection failing.
- Response bodies are capped at 64 MiB after decompression; an entire native call
  has a 60-second deadline in addition to its socket timeouts.

The reference app's automatic headless-WebView path is not ported in this release.
An explicit Cloudflare challenge is identified separately from a restricted work
and can be completed in archive sign-in. This change does not establish that all
525 errors are fixed: Cloudflare-to-origin failures can still occur.

JVM tests exercise the shipped client with synthetic responses, covering headers,
all compression formats, cookie rotation, redirect validation, POST handling,
429 metadata, and single-attempt 525/network failures. Android compilation checks
the packaged native dependencies. No AO3 traffic is generated by these tests;
behaviour on the user's network still requires confirmation on the device.
